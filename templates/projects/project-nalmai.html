Nalmai: Real-Time Teaching Copilot

Code

FastAPI · WebRTC · Speech-to-Text with Diarization · GPT-5.6 Structured Outputs · Bayesian Knowledge Tracing · SQLite · Server-Sent Events · OpenAI Codex

Hackathon Team of 2 · with Laiba Jul 2026

Teachers usually discover that students are confused only after the lesson has moved on. Nalmai is a real-time copilot for online lessons that closes that gap. It listens to the teacher and student separately, detects confusion and risky explanations as they happen, suggests a better teaching move, checks whether the teacher actually used it, runs a quick learning check, and tracks each student's mastery of each concept over time.

Not a chatbot, but a closed loop: detect confusion → recommend a teaching move → verify it was used → measure what happened next.

1) How It Works

Teacher + student WebRTC audio (separate tracks, 10-second windows) → speech-to-text with diarization → speaker-specific transcript → student learning signals teacher explanation risk → Confusion Confidence Score (CCS, deterministic) → GPT-5.6 teaching suggestion → automatic 3-option baseline poll → later teacher speech → implementation verification → follow-up poll → Bayesian Knowledge Tracing mastery + SQLite memory

The language model handles what needs language understanding: classifying student language, analysing explanation risk, drafting suggestions and polls, verifying implementation, and generating memory insights. Every call uses strict structured outputs, so no free-form model text is parsed. CCS, mastery tracking, thresholds, grading and outcome calculations are deterministic Python.

2) Key Features

  • Live two-person lesson: a browser video call with WebRTC signalling over a FastAPI WebSocket. Media stays peer-to-peer.
  • Per-speaker transcription: teacher and student audio tracks are captured and transcribed separately, which avoids mixing up who said what.
  • Confusion Confidence Score: a live, explainable score with time-decayed evidence and student breadth normalised against the class roster.
  • Teacher explanation risk: flags factual and clarity risks, such as a rule stated without conceptual support, before students push back.
  • Suggestions and automatic polls: one strategy-specific re-explanation per confusion spike, plus generated baseline and transfer checks. The correct answer is never sent to the student's screen.
  • Implementation verification: later teacher speech is checked for evidence that the suggestion was used, with a quote and a confidence. The teacher can override it.
  • Per-student, per-concept mastery with Bayesian Knowledge Tracing. Language evidence only affects the student who produced it.
  • Teacher Memory Agent: uses only the current concept's history, stored under pseudonymous IDs, to inform suggestions. The model never gets open access to the database.

These results come from a small set of authored scenarios and are reported with clear limits. TalkMoves validates ingestion of real classroom language, not CCS accuracy, and the matched "nudge vs. control" outcome replay shows the linkage works but is not evidence of a causal learning effect. A classroom pilot with educator-labelled data would be the next step.
